# 學生操作與報告講解稿：AI 校園心靈守護者

## 一句話介紹

我們這組做的是「匿名、非診斷的 AI 校園指揮中心」。它不是判斷誰有病，而是讓國中組用比較進階的方式展示：多來源訊號融合、區域風險判讀、機器人派遣、學生支持與結案證據，幫老師更早看到需要關心的區域。

## 學生操作入口

- 公開展示網址：`https://timdirty.github.io/115-campus-ai-demo/app3/`
- 本機開發版：執行 `npm run dev` 後開啟 Vite 顯示的網址。
- 沒有 Firebase、Gemini 或 Arduino 時也能完整操作，資料會存在瀏覽器本機資料。
- 第一屏最上方有「學生上台模式」：只保留 **開始示範 / 開圖卡 / 機器人幕 / 重置舞台** 四個大按鈕，旁邊會顯示閉環、橋接、圖卡、感測狀態。

## 上台分工建議

- 第一位同學：用「非診斷、匿名、老師確認」說明問題意識與安全邊界。
- 第二位同學：按「開始示範」，讓五段閉環從 0/5 跑到 5/5 並建立關懷事件。
- 第三位同學：打開預警、感知與機器人任務，說明 AI 融合、硬體備援與完成紀錄。

## 第一屏導覽講解稿

大家好，我們是 AI 校園心靈守護者小組。我們的作品不是心理診斷工具，也不收集真實學生個資，而是用匿名資料協助老師更早發現需要關心的情況。

首先在第一屏，只要先看「學生上台模式」這一排大按鈕：開始示範、開圖卡、機器人幕、重置舞台。接著看全校總覽和五段閉環進度。每個區域都有風險、聲量和提醒數，這些資料都是匿名示範訊號，重點是呈現「AI 主動巡查、非診斷、可持續追蹤」。

第一屏也有五段閉環進度：訊號融合、預警成案、派遣處置、學生支持、回報結案。評審如果時間很短，可以直接按「開始示範」，系統會把五段流程跑完並留下紀錄。

如果某個區域變成中高風險，我們可以直接點選它，指派機器人前往介入。這裡的機器人不是取代老師，而是先做柔和提示、引導或通知，接著由老師低壓確認。

接著打開預警抽屜。我們選一筆提醒，勾選處置清單，例如「導師已確認」、「安排關懷談話」或「轉介輔導室」。按下佈署關懷後，系統會新增支持方案，也會留下硬體提示紀錄。

再打開感知抽屜。系統可以用本機麥克風只計算音量和波動，不保存錄音，也不轉文字。AI 會融合心情簽到、聲量、節點和提醒，主動判斷是否需要老師觀察。

感知抽屜也有三張 GPT image 2 生成的「台灣國中校園寫實圖卡」：穿堂下課關懷、閱讀角考前壓力、操場邊緣退縮。這些圖卡可以逐張下載，也可以用工具選單或感知 Tab 的「列印版」開啟整組 A4 列印頁；如果舞台光線或權限不穩，直接按「判讀＋派遣」，系統會建立影像提醒、補上聲量證據、派機器人，並同步到 `robot_app3.jsx` 第二螢幕。

最後打開照護與機器人抽屜。學生支持會留下心情簽到、匿名心情牆與安全空間聊天；機器人抽屜會看到任務進度、底盤控制、節點狀態、硬體提示與結案紀錄，證明整個流程有留下可追蹤證據。

## 操作步驟卡（底部 4 個 Tab：預警 / 感知 / 照護 / 機器人）

1. 最簡單是雙擊 `一鍵啟動展示.command`；如果已經有人開好主控台，就直接看第一屏「學生上台模式」四個大按鈕。
2. 按 **重置舞台**，讓主控台、任務、圖卡判讀與第二螢幕都回到待命狀態。
3. 按 **開始示範**，讓系統從 `0/5` 跑到 `5/5`：「訊號融合 → 預警 → 感知 → 派遣 → 支持 → 結案」。
4. 點 **預警** Tab → 選一筆提醒，勾選處置清單，按「佈署關懷」或「完成閉環」。
5. 點 **感知** Tab → 按「示範」或啟用麥克風，看聲量趨勢圖；也可按「列印版」印整組圖卡，再按「判讀＋派遣」直接跑影像辨識閉環。
6. 點 **照護** Tab → 展示心情簽到、情緒字體、心靈森林與安全聊天。
7. 點 **機器人** Tab → 確認任務進度、底盤控制、節點狀態、硬體提示紀錄與支援方案。
8. 最後展示「工具」裡的匯出/匯入，或按 **重置舞台** 回到下一輪 demo。

## 影像圖卡閉環操作

1. 到 **感知** Tab 的「列印辨識圖卡」區。
2. 按「列印版」開啟 `demo-scenes/guardian-printable-scene-cards.html`，或下載任一張圖卡：`穿堂下課關懷`、`閱讀角考前壓力`、`操場邊緣退縮`。
3. 舞台上可以把圖卡對準攝影機按「擷取判讀」；若攝影機不穩，直接按圖卡上的 **判讀＋派遣**。
4. 主控台會立刻建立影像場域提醒、寫入聲量證據、更新區域風險、派遣機器人。
5. 第二螢幕可從「學生上台模式」按 **機器人幕**，或使用啟動視窗印出的 iPad 網址；網址中的 `bridge` 會覆蓋 iPad 舊設定，避免吃到上次場地的橋接位置。畫面會看到收到任務、目的地與狀態，機器人頁的任務掃描也會回報主控台形成新提醒。

## 評審可能會問

### 這是不是在診斷學生心理狀態？

不是。我們只做關懷提醒和支持建議，不做醫療或心理診斷，也不使用真實學生姓名。

### 為什麼要匿名？

因為心理與情緒資料很敏感。展示時用匿名代號，正式使用也應該先保護隱私，再讓老師或輔導室提供支持。

### 沒有 Firebase、Gemini 或 Arduino 可以展示嗎？

可以。系統目前是 local-first，沒有雲端也能完整操作；沒有 Arduino 時會保留硬體提示紀錄，接上 UNO R4 後同一操作會送到實體提示裝置。

### 機器人出現會不會標籤化學生？

機器人是輔助老師「去關心」，不是去「標記誰有問題」。它會在高風險空間附近做柔和音效或燈號提示，不會貼近特定學生、不會廣播姓名，也不會顯示任何個人資訊。老師看到提示後再用低壓方式確認，決定權永遠在人，不在機器。

### 你們的 AI 只是 if-else 規則，還是真的在做 AI？

我們有三層真正的 AI 融合：① `proactiveGuardian.ts` 把心情簽到分佈、聲量指數、節點狀態、未解提醒四個訊號加權合成一個風險分數，不是單一規則；② `acousticGuardian.ts` 即時分析麥克風波形算音量指數與波動性，而不是只判斷大小聲；③ `localGuardianAi.ts` / Gemini API 根據提醒上下文生成個人化支持建議。這三層結合才觸發派遣決策，比單純 if-else 複雜很多。
