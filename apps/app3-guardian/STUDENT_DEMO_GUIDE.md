# 學生操作與報告講解稿：AI 校園心靈守護者

## 一句話介紹

我們這組做的是「匿名、非診斷的 AI 校園指揮中心」。它不是判斷誰有病，而是讓國中組用比較進階的方式展示：多來源訊號融合、區域風險判讀、機器人派遣、學生支持與結案證據，幫老師更早看到需要關心的區域。

---

## 系統架構

```
電腦（老師/主控）                     iPad / 平板（機器人上）
┌────────────────────────────┐        ┌───────────────────────┐
│  瀏覽器 :3000              │        │  robot-display.html   │
│  主控儀表板（App3）        │        │  AI 心靈守護機器人臉  │
│           ↕                │        │          ↑             │
│  Bridge Server :3203       │──WiFi──│  WebSocket /display   │
│  （橋接 Arduino / iPad）   │        └───────────────────────┘
│           ↕                │
│  Arduino UNO R4 WiFi       │
│    └ L293D 馬達驅動模組    │
│        └ TT 馬達 × 4      │   ← 3D 列印機身，有硬體才需要
└────────────────────────────┘
```

**機器人硬體：** 3D 列印機身 ＋ Arduino UNO R4 WiFi ＋ L293D 馬達驅動模組 ＋ TT 馬達 × 4

**最低需求（無硬體也能完整示範）：**
- MacBook / Windows 電腦一台
- Node.js 18+（`node --version` 確認）
- 現代瀏覽器（Chrome / Edge 建議）

**完整展示（加 iPad 同步）：**
- 電腦 + iPad 同一 WiFi
- iPad 開瀏覽器（Safari / Chrome）

## 快速啟動（2 分鐘）

### 最簡單：雙擊啟動

在 Finder 直接雙擊 `一鍵啟動展示.command`。它會自動：
- 找可用的前端 port
- 啟動 bridge `:3203`
- 重置舞台到待命狀態
- 在終端機印出 iPad 第二螢幕網址

展示結束後，回到啟動視窗按 Enter，或雙擊 `一鍵停止展示.command`。

### 手動啟動（若 .command 無法執行）

```bash
cd "AI校園心靈守護者"
npm install      # 第一次或 pull 後才需要
npm run dev      # 同時啟動前端 :3000 + 橋接 :3203
```

終端機出現：
```
[web]    ➜  Local:   http://localhost:3000/
[bridge] App 3 guardian serial bridge listening on http://localhost:3203
```

### iPad 機器人顯示連線

1. 電腦和 iPad 連到**同一個** WiFi
2. 打開主控儀表板 → 機器人 Tab → 找「機器人顯示・ROBOT FACE」卡片
3. 點「產生 QR 碼」→ iPad 用相機掃碼 → Safari 自動開啟
4. iPad 出現機器人臉 + 綠色「SYNCED」= 連線成功

手動輸入 URL：`http://[電腦IP]:[前端port]/robot-display.html?bridge=[電腦IP]:3203`

## 第一屏導覽講解稿

大家好，我們是 AI 校園心靈守護者小組。我們的作品不是心理診斷工具，也不收集真實學生個資，而是用匿名資料協助老師更早發現需要關心的情況。

首先在第一屏，看「學生上台模式」這一排大按鈕：**開始示範、開圖卡、機器人幕、重置舞台**。接著看全校總覽和五段閉環進度。每個區域都有風險、聲量和提醒數，這些資料都是匿名示範訊號，重點是呈現「AI 主動巡查、非診斷、可持續追蹤」。

五段閉環進度：訊號融合 → 預警成案 → 派遣處置 → 學生支持 → 回報結案。評審如果時間很短，可以直接按「**開始示範**」，系統會把五段流程跑完並留下紀錄。

如果某個區域變成中高風險，我們可以直接點選它，指派機器人前往介入。這裡的機器人不是取代老師，而是先做柔和提示、引導或通知，接著由老師低壓確認。

接著打開預警抽屜。選一筆提醒，勾選處置清單，例如「導師已確認」、「安排關懷談話」或「轉介輔導室」。按下佈署關懷後，系統會新增支持方案，也會留下硬體提示紀錄。

再打開感知抽屜。系統可以用本機麥克風只計算音量和波動，不保存錄音，也不轉文字。AI 會融合心情簽到、聲量、節點和提醒，主動判斷是否需要老師觀察。

最後打開照護與機器人抽屜。學生支持會留下心情簽到、匿名心情牆與安全空間聊天；機器人抽屜會看到任務進度、D-pad 底盤控制、節點狀態、硬體提示與結案紀錄，證明整個流程有留下可追蹤證據。

## 操作步驟（完整版）

### 開場前確認

```
□ npm run dev 已啟動，瀏覽器開著
□ 若有 iPad：掃碼連線確認 SYNCED
□ 點第一屏「重置舞台」清空，從乾淨狀態開始
```

### 步驟 1：校園地圖 + 機器人派遣（60 秒）

```
① 點校園地圖上的高風險區（穿堂、閱讀角或操場邊）
② 側邊卡片出現：點「派遣機器人」
③ 機器人動畫 + Toast「機器人派遣中…」
④ 若有 iPad：觀察機器人臉部切換到「專注」表情
```

### 步驟 2：預警處理（60 秒）

```
① 點底部「預警」Tab
② 點一筆「AI 主動巡查」提醒，展開細節
③ 勾選「導師已確認」→「安排關懷談話」
④ 點「佈署關懷」→ 建立支持方案
⑤ 系統顯示「硬體提示：CARE_DEPLOYED」
```

### 步驟 3：感知中心（45 秒）

```
① 點底部「感知」Tab
② 指出「AI 融合分析」4 條訊號（心情/聲量/節點/提醒）
③ 點「示範高聲量」→ 折線圖出現上升趨勢
④ 說明麥克風只計算音量、不保存錄音、不上傳雲端
⑤ 點「由多來源訊號建立提醒」→ 新增一筆預警
```

### 步驟 4：照護功能（60 秒）

```
① 點底部「照護」Tab
② 點「有點擔心」做心情簽到 → Toast 確認
③ 在心靈森林輸入一則貼文，點「發布」
④ 在聊天框輸入「我今天有點緊張」→ AI 回覆
```

### 步驟 5：機器人 + 紀錄（45 秒）

```
① 點底部「機器人」Tab
② 點「CARE_DEPLOYED 部署關懷」快速指令
③ 展開底部遙控列 → D-pad 測試前後左右
④ 說明：韌體看門狗 3 秒保護，放開自動停車
⑤ 下滑到「硬體提示紀錄」→ 展示操作留存證據
```

### 結尾（15 秒）

```
點右上角「匯出」→ 下載 JSON 檔
說：「整個流程都有可追蹤的記錄，可以匯出給輔導老師參考。」
```

## 評審可能會問

### 這是不是在診斷學生心理狀態？

不是。我們只做關懷提醒和支持建議，不做醫療或心理診斷，也不使用真實學生姓名。

### 機器人是怎麼做的？

機身用 3D 列印製作，控制核心是 Arduino UNO R4 WiFi，馬達驅動採用 L293D 馬達驅動模組，帶動四個 TT 馬達。App 透過 bridge 伺服器把指令（FORWARD / BACKWARD / LEFT / RIGHT / STOP）傳給 Arduino 韌體，韌體再控制 L293D 輸出給馬達。

### 底部遙控列是什麼？

巡邏底盤的手動控制入口，常駐可收折。D-pad 控制前後左右，速度可調；韌體看門狗 3 秒保護，放開按鍵自動停車。收折後只顯示連線狀態與緊急停止按鈕，不佔主畫面空間。

### 為什麼要匿名？

因為心理與情緒資料很敏感。展示時用匿名代號，正式使用也應該先保護隱私，再讓老師或輔導室提供支持。

### 沒有 Firebase、Gemini 或 Arduino 可以展示嗎？

可以。系統目前是 local-first，沒有雲端也能完整操作；沒有 Arduino 時會保留硬體提示紀錄，接上 UNO R4 後同一操作會送到實體機器人。

### 你們的 AI 只是 if-else 規則，還是真的在做 AI？

我們有三層真正的 AI 融合：① `proactiveGuardian.ts` 把心情簽到分佈、聲量指數、節點狀態、未解提醒四個訊號加權合成一個風險分數；② `acousticGuardian.ts` 即時分析麥克風波形算音量指數與波動性；③ `localGuardianAi.ts` / Gemini API 根據提醒上下文生成個人化支持建議。這三層結合才觸發派遣決策，比單純 if-else 複雜很多。

### 聲量偵測會不會侵犯隱私？

不會。瀏覽器麥克風只做本機即時運算，計算音量指標與波動；不保存原始錄音、不轉文字、不上傳雲端。運算後的匿名訊號才寫入 localStorage，整個聲量功能需要學生主動開啟。

## 疑難排解

| 問題 | 解法 |
|---|---|
| 橋接伺服器連不上 | `lsof -i :3203` 確認；重啟 `npm run dev` |
| iPad 無法連線 | 確認同一 WiFi；macOS 防火牆允許傳入連線；手動輸入 URL |
| 感知 Tab 出現「趨勢資料收集中」 | 麥克風尚未採樣，按「示範高聲量」注入示範數據（正常現象） |
| 資料異常 / 想重置 | 點右上角「重置」圖示 → 確認清除 → 恢復初始示範資料 |
| 瀏覽器 localStorage 損毀 | 瀏覽器 Console：`localStorage.removeItem('guardian-state:v3'); location.reload()` |
| 機器人不動 | 確認 UNO R4 已接電、在同一 WiFi；Arduino 串口連線正常；橋接確認 `arduinoConnected: true` |

| 有點擔心 + 中低風險 | 焦慮 (anxious) | 擔憂眉 |

## 硬體指令速查

| 指令 | 說明 |
|---|---|
| `FORWARD` | 前進 |
| `BACKWARD` | 後退 |
| `LEFT` | 左轉 |
| `RIGHT` | 右轉 |
| `STOP` | 停止 |
| `PATROL_START` | 開始巡邏 |
| `SPEED:<0-255>` | 設定速度 |
| `ALERT_SIGNAL` | 警示訊號（LED 閃爍） |
| `CARE_DEPLOYED` | 關懷已佈署提示 |
| `NODE_RESTART` | 節點重新連線 |
| `HEARTBEAT` | 看門狗心跳（每 3 秒） |
