# 學生操作與報告講解稿：校園服務機器人 App

## 一句話介紹

我們這組做的是「校園服務機器人中控台」。它可以把福利社配送、教學協助、清潔廣播、校園巡邏和安全任務整合在同一個 App 裡，讓機器人不只是單一功能，而是校園裡的任務助手。

## 機器人硬體

- **底盤**：自行 3D 列印車架
- **控制板**：Arduino UNO R4 WiFi
- **馬達驅動**：L293D 模組
- **驅動輪**：TT 馬達 × 2（M1 + M2）
- **清掃滾筒**：TT 馬達 × 2（M3 + M4）
- **通訊方式**：App → bridge 伺服器 → USB Serial → Arduino → L293D → TT 馬達

## 學生操作入口

學生只要記住一句話：

「校園服務機器人會看見問題、派出任務、留下紀錄。」

上台只做四個按鈕：

1. 開始：影像任務。
2. 教學：點名互動。
3. 配送：下單追蹤。
4. 生活：事件派遣。

展示前準備：

1. 雙擊 `一鍵啟動展示.command`。
2. 等瀏覽器自動開啟。
3. 展示時不要關閉啟動視窗。
4. 進入「學生展示模式」後，照畫面上的四個大按鈕：開始、教學、配送、生活。
5. 展示結束後，回到啟動視窗按 Enter 關閉。

## 機器人顯示端聯動

如果現場有 iPad 或第二個螢幕，可以打開機器人顯示端，讓評審看到 App 任務真的同步到機器人臉：

1. 主控 App 右側打開「機器人顯示面板」。
2. 按「產生 QR 碼」，iPad 掃描後會開啟 `robot-display.html`。
3. 學生按「開始、教學、配送、生活」時，機器人顯示端會同步顯示目前任務，例如「人流疏導、配送服務、教學協助」。
4. 沒有 iPad 也可以點「在新分頁預覽機器人顯示」，用同一台電腦展示。

這條聯動代表閉環是：學生操作 App → 任務與硬體紀錄更新 → 機器人顯示端同步表情與任務語句。

## 上台分工建議

- 第一位同學：講一句話介紹並按「開始」做影像 / 生活服務任務。
- 第二位同學：按「配送」，完成下單、追蹤到達與 robot display 說明。
- 第三位同學：按「教學 / 生活」，說明點名、事件派遣、報表紀錄與備援。

## 3 分鐘講解稿

大家好，我們是校園服務機器人小組。我們觀察到學校裡有很多重複性工作，例如福利社配送、清潔提醒、廣播、巡邏、上課點名和安全通報。如果每一件事都分開做，老師和行政人員會很忙，所以我們設計一個校園機器人中控台。

我們的機器人底盤是自己用 3D 列印做的，用 Arduino UNO R4 WiFi 當大腦，透過 L293D 馬達驅動 IC 控制四顆 TT 馬達，兩顆帶動輪子、兩顆帶動清掃滾筒。App 下達指令後，指令從 bridge 伺服器透過 USB Serial 傳到 Arduino，Arduino 再控制馬達動作。

首先在學生展示模式可以看到四個大按鈕。每個按鈕都代表一段校園服務，不只是切換畫面，而是會留下任務紀錄。

接著我們進入配送頁，下訂一筆福利社商品。送出後，系統會扣庫存、建立訂單、指派機器人。如果庫存不足，系統只會記錄提醒，不會誤派機器人。

再到追蹤頁，我們可以把配送任務標記為送達，機器人收到 DELIVERY_DONE 指令後待命回位。接著可以展示教學頁，例如點名、學生提問回覆或分心提醒，代表機器人也可以協助課堂。

最後我們到生活服務。它可以把校園事件變成廣播、巡邏或清掃任務，讓評審看到機器人真的有接到任務。

## 上台操作步驟卡

學生版只看四個大按鈕，讓評審看見完整閉環：

1. 開始：按「影像任務」，讓機器人看校園畫面。
2. 教學：按「點名互動」，完成點名、處理課堂訊號，再到學生報告。
3. 配送：按「下單追蹤」，系統會建立訂單、扣庫存、派機器人並進入追蹤。
4. 生活：按「事件派遣」，把校園事件變成廣播或巡邏任務。

同學只要照畫面按，不需要找後台功能。每一步都會留下任務、點名、訂單或派遣紀錄，所以不是假切頁。

可以照這句開場：

「機器人會看見問題，派出任務。」

「最後留下紀錄，給老師和評審看。」

影像任務只做三件事，形成辨識閉環：

1. 按「開始影像任務」。
2. 等畫面出現簡單結果、信心度、辨識來源和畫面品質。
3. 按「派遣任務」，確認任務紀錄新增後再按「下一個展示」。

加分展示再做：

1. 到配送頁選一個商品。
2. 按下下單。
3. 到首頁看任務紀錄。

## 生活影像辨識展示話術

學生展示模式會依序跑五個固定校園情境：

1. 人流疏導。
2. 安全巡查。
3. 清掃需求。
4. 配送服務。
5. 一般巡邏。

操作同學只要照三步走：

1. 點學生展示模式的「開始影像任務」。
2. 等畫面下方出現「發現人流、需要清掃、可以巡邏」這類簡單結果。
3. 按下派遣按鈕，完成後按「下一個展示」。

可以照這樣講：

「這裡不是單純按按鈕。系統會先看校園畫面，顯示信心度和畫面品質，再把結果變成任務。按下派遣後，任務會進入紀錄，所以流程是辨識、派遣、紀錄的閉環。」

## 評審可能會問

### 這是不是只有按鈕切頁？

不是。主要操作會同步改變庫存、訂單、任務、機器人狀態和服務紀錄。

### 如果商品沒庫存會怎樣？

系統會阻止錯誤任務，只留下提醒紀錄，不會派遣機器人。

### 沒有 Arduino 可以展示嗎？

可以。展示流程會先讓同學完成任務建立、派遣、追蹤和報表；接上實體機器人後，同一套操作可以同步到硬體。

### 影像辨識是不是假的？

不是。展示流程會先看目前校園畫面；如果現場網路不穩，也會用安全展示流程接住，讓同學能穩定完成辨識、派遣和紀錄。

### 機器人用什麼硬體？

3D 列印底盤 + Arduino UNO R4 WiFi + L293D 馬達驅動模組 + TT 馬達 × 4。App 送指令 → bridge → USB Serial → Arduino → L293D → 馬達轉動。

### 搖桿可以控制真實機器人嗎？

可以。右下角 FAB 搖桿送出 FORWARD／BACKWARD／LEFT／RIGHT／STOP 指令，bridge 轉給 Arduino，韌體有 3 秒看門狗保護，放開搖桿自動停車。

## 後續機器人連動計畫

1. `DELIVERY_START`、`DELIVERY_DONE`、`BROADCAST_START`、`PATROL_START`、`SWEEP_START`、`SWEEP_STOP` 已會進入 App 任務紀錄，也會推送到機器人顯示端。
2. 指令透過 bridge → USB Serial 送到 UNO R4，UNO R4 控制 L293D 驅動 TT 馬達執行動作。
3. 保留 App 的展示流程，讓比賽現場即使設備臨時不穩，也能完成學生操作與任務說明。
