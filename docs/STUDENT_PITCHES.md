# Student Demo Pitches

這份講稿給三隊上台前練習用。每隊都有 1 分鐘、3 分鐘、5 分鐘版本，可以依比賽時間縮放。

## 國小隊伍 1 - AI 自動板擦機器人

### 三位上台分工

- 第一位同學：開場說明教室問題與作品目標，負責把「先保存、再擦除」講清楚。
- 第二位同學：操作拍白板與教師看板，產生白板分析、保存決策並派出主線任務。
- 第三位同學：展示機器人任務、紀錄本、小老師與學習單，回答硬體與備援問題。


### 1 minute

大家好，我們是國小隊伍 1。我們的作品是「AI 自動板擦機器人」，它要解決的是：白板 AI 助教、教師決策、課堂紀錄與機器人指令展示。

先跑「白板拍照閉環」：我先拍白板，AI 會告訴老師哪裡可以擦，最後機器人留下完成記錄。 操作順序是 拍白板或上傳白板樣張。 -> 看本機像素辨識，指出有筆跡的區塊。 -> 老師保存決策，派板擦機器人或模擬任務。 -> 白板區塊出現完成標記，任務 log 留下證據。。完成時要指給評審看：像素分析結果、老師決策紀錄、白板 ✓ 覆蓋層、任務 log / bridge ack。

硬體連動部分，我們預留 LEGO EV3 角色：「白板筆臂 / 板擦路徑展示」。沒有接硬體時也能用模擬模式完整展示；接上 EV3 後，會使用 `EV3_STATUS`, `EV3_CALIBRATE`, `EV3_PEN_DOWN`, `EV3_PEN_UP`, `EV3_DRAW_LINE`, `EV3_HOME`, `EV3_STOP` 等指令。

### 3 minutes

我們選這個題目，是因為校園裡有很多重複、即時、需要安全判斷的工作。AI 自動板擦機器人 把畫面、資料或感測訊號整理成學生和老師看得懂的任務流程。

這個作品的技術重點有三個。第一，前端是完整可操作的 app，不是只有簡報畫面。第二，系統有本機備援邏輯，AI 或網路不穩時仍能展示主要流程。第三，機器人指令已經整理成 catalog，未來接 EV3 時不用重寫作品。

第一條主線跑「白板拍照閉環」。目的：把白板照片變成擦除建議，再由老師確認後派機器人執行。 AI / 辨識來源是：瀏覽器 canvas 像素辨識；Gemini 只用來補充說明，沒有 key 也能完成。。硬體或模擬指令會用 `ERASE_REGION_A`, `ERASE_REGION_B`, `EV3_STATUS`, `EV3_STOP`。完成後用 像素分析結果、老師決策紀錄、白板 ✓ 覆蓋層、任務 log / bridge ack 當證據；如果現場卡住，說法是：相機、Gemini、Arduino 或 EV3 任一失敗時，改用白板樣張與模擬 log，仍能展示同一條流程。

第一條主線跑「課堂筆記閉環」。目的：證明機器人不是只會擦白板，而是先把要保留的學習內容存起來。 AI / 辨識來源是：本機模板摘要加 Gemini 可選文字整理；沒有網路時仍保留筆記與問答入口。。硬體或模擬指令會用 `EV3_STATUS`。完成後用 課堂摘要、紀錄本資料、小老師問答、匯出或展示紀錄 當證據；如果現場卡住，說法是：AI 回覆失敗時，使用本機摘要與既有筆記示範保存價值。

### 5 minutes

完整展示可以分成問題、解法、AI、硬體、備援五段。

問題：白板 AI 助教、教師決策、課堂紀錄與機器人指令展示。

解法：這組有 3 條閉環路線，主線給 3 分鐘展示，支線回答 AI、硬體與真實場景追問。

「主線：白板拍照閉環」負責回答一個評審追問。學生說法：我先拍白板，AI 會告訴老師哪裡可以擦，最後機器人留下完成記錄。 依序做 拍白板或上傳白板樣張。 -> 看本機像素辨識，指出有筆跡的區塊。 -> 老師保存決策，派板擦機器人或模擬任務。 -> 白板區塊出現完成標記，任務 log 留下證據。；成功證據是 像素分析結果、老師決策紀錄、白板 ✓ 覆蓋層、任務 log / bridge ack；備援說法是 相機、Gemini、Arduino 或 EV3 任一失敗時，改用白板樣張與模擬 log，仍能展示同一條流程。

「加分：課堂筆記閉環」負責回答一個評審追問。學生說法：擦白板前，我會先把今天的重點存成筆記，等一下還能問小老師複習。 依序做 從白板內容或逐字稿建立課堂重點。 -> AI 把內容整理成學生看得懂的摘要。 -> 存進紀錄本，打開小老師問答。 -> 展示筆記與複習紀錄，證明內容沒有被擦掉。；成功證據是 課堂摘要、紀錄本資料、小老師問答、匯出或展示紀錄；備援說法是 AI 回覆失敗時，使用本機摘要與既有筆記示範保存價值。

「硬體：校準 / 遙控閉環」負責回答一個評審追問。學生說法：老師先測前後左右和停止，看到 log 回來，才讓機器人去擦白板。 依序做 老師開啟硬體控制面板。 -> 測試前進、後退、左轉、右轉與停止。 -> 韌體 watchdog 或模擬 log 回報最後指令。 -> 任務面板顯示最後一次硬體動作。；成功證據是 bridge health、最後指令、watchdog / STOP log、任務面板更新；備援說法是 真機未接上時打開模擬模式，照樣展示同一批指令與安全停止說法。

硬體：EV3 指令已先規劃成 `EV3_STATUS`, `EV3_CALIBRATE`, `EV3_PEN_DOWN`, `EV3_PEN_UP`, `EV3_DRAW_LINE`, `EV3_HOME`, `EV3_STOP`。這代表 app 端、bridge 端、EV3 server 端可以用同一份指令語言溝通。

備援：如果相機、AI、EV3 或 Arduino 其中一個現場不穩，作品仍能開啟、操作、記錄任務，並用模擬模式說明接上硬體後的真實動作。

## 國小隊伍 2 - 校園服務機器人

### 三位上台分工

- 第一位同學：講一句話介紹並按「開始」做影像 / 生活服務任務。
- 第二位同學：按「配送」，完成下單、追蹤到達與 robot display 說明。
- 第三位同學：按「教學 / 生活」，說明點名、事件派遣、報表紀錄與備援。


### 1 minute

大家好，我們是國小隊伍 2。我們的作品是「校園服務機器人」，它要解決的是：配送、清潔、教學、生活服務與派遣中控台。

先跑「福利社配送閉環」：我幫同學下一筆訂單，系統確認有庫存後，機器人就去配送並留下紀錄。 操作順序是 學生選商品並送出訂單。 -> 系統檢查庫存，決定是否派遣。 -> Arduino / EV3 / robot display 同步顯示任務狀態。 -> 到達確認後，報表留下完整服務紀錄。。完成時要指給評審看：庫存扣減、訂單紀錄、任務 log、到達時間戳、報表紀錄。

硬體連動部分，我們預留 LEGO EV3 角色：「配送旗標 / 服務機器人手臂展示」。沒有接硬體時也能用模擬模式完整展示；接上 EV3 後，會使用 `EV3_STATUS`, `EV3_ARM_EXTEND`, `EV3_ARM_RETRACT`, `EV3_SAFE_POSE`, `EV3_STOP` 等指令。App 右下角的手動遙控中心可以用虛擬搖桿直接控制底盤方向與滾筒，放開搖桿自動停車。

我們選這個題目，是因為校園裡有很多重複、即時、需要安全判斷的工作。校園服務機器人 把畫面、資料或感測訊號整理成學生和老師看得懂的任務流程。

第一條主線跑「福利社配送閉環」。目的：從學生下單到庫存檢查、機器人派遣、送達確認與報表紀錄。 AI / 辨識來源是：本機規則先做庫存與任務判斷；AI 只用於補貨與派遣說明，沒有 key 也能跑主線。。硬體或模擬指令會用 `DISPATCH_DELIVERY`, `EV3_ARM_EXTEND`, `EV3_ARM_RETRACT`, `STOP`。完成後用 庫存扣減、訂單紀錄、任務 log、到達時間戳、報表紀錄 當證據；如果現場卡住，說法是：沒有 Arduino / EV3 時改用模擬派遣與 robot display，保留同樣的任務紀錄。

第一條主線跑「教學助手閉環」。目的：把老師點名或提醒變成教學服務任務，並讓機器人狀態同步回報。 AI / 辨識來源是：本機班級規則與可選 AI 摘要；斷網時仍能建立教學任務。。硬體或模擬指令會用 `TEACH_ATTENDANCE`, `DISPLAY_EMOTION`, `EV3_STATUS`。完成後用 點名結果、教學服務任務、robot display 狀態、報表紀錄 當證據；如果現場卡住，說法是：AI 無回應時以本機點名結果和任務卡完成示範。

完整展示可以分成問題、解法、AI、硬體、備援五段。

問題：配送、清潔、教學、生活服務與派遣中控台。

## 國中隊伍 - AI 校園心靈守護者

### 三位上台分工

- 第一位同學：用「非診斷、匿名、老師確認」說明問題意識與安全邊界。
- 第二位同學：操作主線示範，讓五段閉環從 0/5 跑到 5/5 並建立關懷事件。
- 第三位同學：展示預警、感知、機器人任務與硬體備援紀錄，回答 AI 融合問題。


### 1 minute

大家好，我們是國中隊伍。我們的作品是「AI 校園心靈守護者」，它要解決的是：匿名關懷、預警處理、自我照護、聊天與節點監控。

先跑「心情關懷閉環」：同學匿名說出心情，AI 只提醒需要老師確認，不做診斷，最後留下關懷紀錄。 操作順序是 匿名輸入心情或啟動主線示範。 -> 本機守護 AI / Gemini 產生低壓回覆。 -> 建立關懷事件，老師確認處理。 -> 結案時間線留下預警、派遣與照護證據。。完成時要指給評審看：匿名心情、AI 低壓回覆、老師確認、關懷結案時間線。
